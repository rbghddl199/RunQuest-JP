# RunQuest デモガイド

## 要点

RunQuest は、ユーザーのアンケート・ランニング記録・現在地をもとに、その日走るのに適した大田(テジョン)地域のランニングコースを推薦し、ランニング記録をコミュニティと連携させる AI ベースのランニング推薦サービスです。

## 解決したい課題

- 初心者はどこでどれくらい走ればよいか判断しづらい。
- 既存のランニングアプリは記録保存には強いが、次に走るコースの推薦は弱いことが多い。
- 天気・位置・体調・過去記録がバラバラに存在し、ユーザー自身が総合判断しなければならない。
- ランニング後に記録を共有したり、コースとして再利用したりする導線が使いにくい。

## RunQuest の解決アプローチ

1. アンケートをもとに新規ユーザーの好みを把握する。
2. ランニング記録が蓄積されると、実際の距離・ペース・コースタイプを推薦に反映する。
3. 位置情報の権限があれば、近いコースを優先的に推薦する。
4. GPS またはシミュレーションモードでランニングを記録する。
5. 自由ランニング完了後、そのまま自分のコースとして保存できる。
6. コミュニティでコースとランニング記録を紐づけて共有する。
7. チャットボットが現在の状況に合わせて対話形式でコースを推薦する。

## 推薦アルゴリズムの説明

推薦は説明可能なスコアベースの方式です。

| ユーザー状態 | 推薦基準 |
| --- | --- |
| 新規ユーザー | アンケート結果中心 |
| 既存ユーザー | アンケート + 直近のランニング記録 |
| 復帰ユーザー | アンケート + 過去記録 + 安全補正 |
| 位置情報提供ユーザー | コース起点との距離を優先反映 |

生成AIは最終的なランキング自体を決定するものではありません。コース推薦理由、チャットボット応答、ランニングフィードバック文を自然な文章にする補助的役割を担います。

## 推奨デモ手順

1. ホーム画面で本日のサマリー、推薦、ミッションを表示する。
2. 推薦画面で推薦コースと推薦理由を説明する。
3. チャットボットに「今日は軽く3kmくらい走りたい」のような文を入力し、対話形式の推薦を見せる。
4. コース詳細またはランニング開始画面で Kakao Map の経路を表示する。
5. シミュレーションモードでランニングを開始し、距離・時間・ペースが自然に増加していく様子を見せる。
6. ランニング完了ページで地図・記録・フィードバックを確認する。
7. 自由ランニング記録を自分のコースとして保存できることを説明する。
8. マイコース画面でブックマーク・自作コース・GPX コースが分類される流れを見せる。
9. コミュニティで投稿・コメント・いいね・保存、関連コース/記録の連携を見せる。
10. マイページで出席状況・バッジ・累積記録を見せる。

## アピールしたい技術ポイント

- Django REST Framework ベースの REST API
- JWT 認証とユーザー設定管理
- GPX 解析による実際のコース座標の反映
- GPS モードとシミュレーションモードの分離
- 自由ランニング完了後のユーザーコース保存
- コミュニティ一覧 API のクエリ最適化
- リクエスト/関数単位のパフォーマンスログ
- Kakao Map ベースの経路可視化
- LLM/OpenAI の任意連携とローカル fallback

## 限界と今後の改善

- 実機モバイル GPS での長時間検証がさらに必要。
- 本番運用では SQLite から PostgreSQL への移行が必要。
- コミュニティ画像は base64 JSON ではなく media URL または S3 方式へ改善できる。
- 推薦アルゴリズムは、ユーザー行動ログが蓄積されれば協調フィルタリングや埋め込みベースの推薦へ拡張できる。
