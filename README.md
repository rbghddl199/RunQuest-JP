# RunQuest

RunQuest は、ユーザーのアンケート結果・ランニング記録・現在地・天気情報をもとに、その日にぴったりの大田(テジョン)地域のランニング/ウォーキングコースを AI が推薦し、記録管理とコミュニティ機能を提供する Web サービスです。

> 本ドキュメントは日本語話者向けに作成したポートフォリオ資料です。アプリ自体の画面表示は韓国語のままですが、プロジェクトの設計思想・実装内容はすべて本ドキュメントで日本語で解説しています。

## プロジェクト概要

一般的なランニングアプリは記録の保存や統計表示に重点を置いているものが多く、「今日どこをどれくらい走ればいいか」を提案してくれるものは多くありません。RunQuest は記録管理に加えて、コース推薦・GPX ベースのコース管理・コミュニティ連携・チャットボット推薦・バッジや出席による継続動機付けまでを一体的に提供することを目指しました。

検証可能な範囲を明確にするため、対象地域は大田(テジョン)エリアに限定し、実在するコースの GPX データを取り込んで Kakao Map 上に実際の経路を表示できるようにしています。

### 実装済みの機能

- 会員登録・ログイン(JWT 認証)
- アンケートに基づくコース推薦
- GPT を用いた推薦理由の自然文生成
- GPS を用いた位置情報取得・記録
- 実データと合成データを組み合わせたコース/記録データ構築
- ランニング記録の保存
- コミュニティ投稿の作成・閲覧
- コメント・いいね機能
- バッジシステム

### 未実装・今後の改善予定

- クラウド環境へのデプロイ
- ユーザー行動データの蓄積による精度向上
- 推薦アルゴリズムの高度化(協調フィルタリング等)
- リアルタイム位置追跡の強化
- Android アプリ化のさらなる改善

## 主な機能

**1. AI コース推薦**
アンケート結果とランニング記録をもとに、ユーザーに合ったコースを推薦します。チャットボットに追加条件を伝えることで、より細かい条件に沿った推薦も受けられます。

**2. GPS ベースの記録測定**
ユーザーの同意のもとで位置情報を取得し、ランニング開始から終了までの記録を測定・保存します。

**3. コミュニティ**
投稿・コメント・いいね機能を通じて、ユーザー同士で情報を共有できます。

**4. バッジシステム**
ランニング目標の達成状況に応じてさまざまなバッジを獲得でき、継続的なモチベーション維持につながります。

**5. マイページ**
個人の記録・活動履歴・各種設定を管理できます。

## 生成AIの活用箇所

### 1. AI によるパーソナライズド コース推薦

ユーザーのアンケート結果と直近 20 回のランニング記録を分析し、AI が個人に最適なコースを推薦します。単にコースを提示するだけでなく、推薦理由も同時に生成することで、ユーザーが結果を直感的に理解できるようにしています。

- **活用データ**: アンケート結果 / 直近 20 回のランニング記録 / 大田地域のコースデータ
- **AI の役割**: ユーザー傾向の分析、コース適合度の評価、推薦コースと理由文の生成

### 2. AI チャットボットによるコース推薦

基本の推薦結果がユーザーの好みに合わない場合、チャットボットとの対話でより具体的な条件のコースを推薦してもらえます。例えば「今日は夜景がきれいなコースを教えて」「3km くらいの短い散歩コースを知りたい」のような自然文の要望を AI が解釈し、適切なコースを提示します。

- **AI の役割**: 自然文の意図理解、要望の分析、パーソナライズされたコース推薦と説明生成

### 3. ランニングフィードバック

ランニング終了後、記録データをもとに AI が簡単なフィードバックを提供します。過去の記録と比較してペース・距離・運動量の変化を分析し、分かりやすい文章で伝えます(例:「今日は前回より平均ペースが 20 秒速くなりました」)。単なる記録保存にとどまらず、継続的なモチベーション向上を目的として実装しました。

- **AI の役割**: ランニング記録の分析、過去記録との比較、パーソナライズされたフィードバック生成

## 推薦アルゴリズムの技術的な説明

既存のランニングアプリの多くは、全ユーザーに似たようなコースを提示するか、初心者や休止明けユーザーの状態を十分に反映できていません。RunQuest はユーザーを「新規」「既存」「復帰」の 3 状態に分類し、それぞれに適した推薦方式を適用します。

| ユーザー状態 | 推薦方式 |
| --- | --- |
| 新規ユーザー | ランニング記録がないためアンケートベースで推薦。アンケートでは経験年数・希望ペースなどの情報を取得し、スコア化して AI 推薦に反映 |
| 既存ユーザー | アンケートと直近 20 回のランニング記録を合わせて反映。新規ユーザーと異なり位置情報も加味 |
| 復帰ユーザー | 直近 30 日以上完走記録がないユーザーが対象。アンケートと過去記録のスコアに安全補正を追加 |

推薦結果には GPT API を用いて自然文の推薦理由を追加生成しています。最終的なコースのランキング自体はルールベースのスコアリングで決定しており、生成AIはあくまで説明文生成の補助的役割です。外部AI呼び出しが失敗してもローカル fallback により機能は維持されます。

## データベース設計 (ERD)

主要エンティティは User、SurveyResponse(アンケート回答)、Course(コース)、CustomCourse(ユーザー作成コース)、RunningRecord(ランニング記録)、CommunityPost/CommunityComment(コミュニティ投稿・コメント)、Badge(バッジ)、ChatSession/ChatMessage(チャットボット)などです。

詳細な ER 図とフィールド定義は [docs/ERD.md](docs/ERD.md) にまとめています。

## セットアップ方法

実際にローカルで動作確認した手順です(バックエンド: Django + SQLite、フロントエンド: Vite)。

```bash
# バックエンド
cd backend
python -m venv .venv
.venv/Scripts/activate        # Windows の場合。macOS/Linux は source .venv/bin/activate
pip install -r requirements.txt
cp ../.env.example ../.env     # 値を必要に応じて設定
python manage.py migrate
python manage.py load_runquest_fixtures --reset   # デモ用データ投入(任意)
python manage.py runserver 127.0.0.1:8000

# フロントエンド(別ターミナル)
cd frontend
cp .env.example .env
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

`http://127.0.0.1:5173` にアクセスすると画面が表示されます(画面表示は韓国語です)。デモアカウントは [docs/PRESENTATION.md](docs/PRESENTATION.md) に記載しています。

外部 API(LLM/OpenAI・OpenWeather・Kakao Map)のキーが未設定でも、天気は既定値表示・AI応答はローカル fallback により、アプリ自体は問題なく動作するように設計しています。

## 開発を通じて学んだこと

**技術面**

Vue3 / Pinia / Vue Router を用いた画面構成と状態管理、Django REST Framework による RESTful API の設計・実装を実践的に学びました。OpenAI 互換の LLM API を用いた AI 機能では、ユーザーのアンケート結果とランニング記録から推薦結果を生成する一連の流れを構築しました。データベース設計では ER 図の作成とモデリングを通じて、データ間の関係設計の考え方を身につけました。また Capacitor を用いて Web アプリをデモ用 Android アプリへ変換し、GPS 機能と Kakao Map API を連携させて位置情報サービスを実装しました。

**苦労した点**

最も苦労したのはフロントエンドとバックエンドの連携部分でした。GPS 機能の実装では、実際の位置データを取得し地図上に経路を表示する処理が想定より複雑であることが分かりました。AI 推薦機能についても、単に GPT を呼び出すだけでなく、ユーザーデータをスコア化して推薦結果を生成するロジック設計に苦労しました。加えて、Web 環境では正常に動作していた機能がアプリ環境では動作しないという問題が発生し、CORS 設定やネットワーク接続の問題解決に多くの試行錯誤を重ねました。

**感じたこと**

このプロジェクトを通じて、単に機能を実装するだけでなく、サービス全体を設計する経験を積むことができました。特にフロントエンド・バックエンド・データベース・AI API をすべて連携させることで、サービス全体の動作フローを理解できました。問題が発生した際に原因を特定し解決する過程で開発力が向上し、実サービスの運用にはデプロイやサーバー運用についてさらなる学習が必要だと実感しました。またチーム開発を通じて、企画と役割分担の重要性を体感しました。

**補足**

Web での実装に加えて、アプリ環境でのデモにも挑戦しました。アプリ環境では実際のデプロイの代わりに、デモ目的で ngrok を使用しています。現在バックエンドサーバーは開発者の PC 上で動作し、ngrok を通じて外部ネットワークからアクセス可能な構成にしています。また Vue で開発した Web サービスを Capacitor で Android アプリに変換し、実際のスマートフォン環境で動作する様子を実現しました。今後は AWS のようなクラウド環境へのデプロイを行い、実サービスとして運用することを目標としています。
